# 验证组织

已初始化 pytest，根目录执行 `uv sync --locked --dev` 后运行 `uv run --locked pytest`。M1/M2/M3 的 `tests/test_health.py` 各含 3 个用例，TestClient 真实执行 ASGI 应用，验证健康响应、错误方法和未知路径，不 mock 路由。pytest 使用 importlib 模式收集同名测试。验证记录见 [INIT-002](../docs/requirements/INIT-002-dev-environment.md)。

模块内测试随代码维护；此目录后续加入契约、真实网络集成、端到端及迁移验证。当前没有业务集成或数据库验证，TestClient 不等同于跨模块网络集成。命令见[根 README](../README.md#本地开发与基础验证)。

关键验证：权限/院系限制、预约整点与可配 4 小时上限、每日签到编码、提醒/取消三个时间点、违约释放、M2 时段占用与撤销、M3 下架与验收恢复、多来源并存/追溯、重复或失败写回、空库迁移及旧数据升级。未定政策先形成验收标准。

禁止常量断言、mock 被测逻辑或用模拟接口冒充链路打通。关键规则经可控破坏/故障注入验证测试失败，再恢复并记录证据。测试库与生产隔离，用合成数据，协调部署窗口。文档初始化只验证目录/链接/差异，不构造无意义业务测试。
