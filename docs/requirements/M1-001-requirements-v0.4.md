# M1 自习座位预约模块需求规格说明书 V0.4

项目名称：校园资源服务平台  
模块：M1 — 个人自习座位预约  
版本：V0.4  
状态：需求评审稿  
适用阶段：第一次功能迭代  
关联模块：D（公共资源与身份）、M2（整教室预约）、M3（维修管理）

## 一、模块目标与边界

### 1.1 业务目标

M1 为学生提供自习教室浏览、座位查询、时间轴查看、座位预约、签到、取消、提前结束、历史查询和违约管理功能。

系统自动处理个人座位预约，不设置人工审批环节。第一次迭代实现完整个人预约闭环，并与 D 的统一资源占用能力集成。

本次范围以浏览器页面、后端接口和数据库记录可直接演示的功能为主，不依赖现场设备、外部消息渠道或专用管理平台。系统取消、违约和完成结果均通过“我的预约”查询。

### 1.2 职责划分

M1 负责：

- 个人座位预约的资格和时间规则。
- 预约记录的创建、查询、取消和状态管理。
- 签到、超时未签到和违约处理。
- 签到后的提前结束与自然完成。
- 根据 D 返回的占用信息展示座位时间轴。
- 接收 D 转发的维修停用通知，取消受影响的个人预约。

D 负责：

- 统一身份认证、角色权限和资源访问范围。
- 教室与座位主数据，包括位置、开放时间、插座属性和长期禁用状态。
- 统一资源可用性查询。
- 个人座位、整间教室的原子占用、截短与释放。
- 座位占用、整室占用、停用限制及用户跨座位重叠占用的统一冲突检查。
- 资源限制来源追溯、紧急停用协调，以及向受影响模块传递停用结果。

M2 负责：

- 整间教室申请、用途和两级人工审批。
- 向 D 请求建立或撤销整室占用。
- 整室预约状态，以及维修导致系统取消后的业务处理。

M3 负责：

- 报修、紧急程度与影响范围确认。
- 派单、维修进度和验收。
- 向 D 请求建立紧急停用或计划施工限制。
- 确认恢复使用条件后，请求解除对应限制。

M1 不负责教室预约审批和维修安全判断。各模块通过公开接口交互，不直接读写其他模块的业务表。资源占用以 D 为唯一权威来源，个人预约业务状态以 M1 为唯一权威来源。

### 1.3 设计原则

本模块以完成个人自习座位预约闭环为核心，优先实现能够通过网页操作、后端接口和数据库记录直接验证的功能，控制第一次迭代的开发范围。

- **流程简洁**：个人预约自动确认，不设置人工审批；学生在“我的预约”中完成签到、取消和提前结束。
- **公平使用**：通过预约时长、每日额度、时间重叠检查和未签到处理，减少长期占座与重复占用。
- **职责清晰**：M1 管理个人预约业务，D 统一管理资源占用，M2、M3 分别负责整室审批和维修判断。
- **实现适度**：不依赖现场设备、扫码、定位或人脸识别，不建设独立通知中心和复杂运营平台。点击签到仅表示本人确认使用，不作为实际到场证明。
- **结果明确**：学生通过预约记录查看操作结果；系统保留必要的状态和时间信息，支持查询与功能验收。

## 二、用户角色与访问控制

### M1-R01 用户登录

教室浏览、座位查询、预约、本人记录查询、取消、签到和提前结束均须登录。

M1 从 D 的可信认证信息中获取当前用户 ID、角色和资源访问范围，不信任前端自行传入的预约人身份。仅具有个人预约权限的学生可创建预约。

### M1-R02 无人工审批

学生提交预约后，系统自动校验资格、时间规则与资源冲突。全部通过后立即确认，不设置待审批状态和人工放行流程。

### M1-R03 个人预约隐私

学生只能查询和操作本人的预约记录。后端对每次查询、取消、签到和提前结束独立校验预约归属。

公共座位时间轴仅展示占用时段和公开原因，不返回其他学生的预约 ID、身份信息或预约详情。“公共”指有资源访问权限的用户可查看，不表示匿名公开。

## 三、前端查询与时间轴

### M1-F01 选择自习教室

展示当前用户有权访问且支持个人预约的教室名称、位置、座位数量和开放时间。支持按位置筛选教室。

选择教室后进入座位页面。长期禁用的教室不允许预约，并明确展示禁用状态。

### M1-F02 选择座位

以规则网格展示座位编号、插座等基础属性，支持“有插座”筛选。第一版不要求精确教室平面图。

学生点击座位后，查看指定日期的时间轴。长期禁用的座位明确标识且不可预约。

### M1-F03 可视化时间轴

时间轴覆盖每日 07:00～22:00，以 30 分钟为最小展示刻度。

| 主色 | 含义 | 是否阻止预约 |
| --- | --- | --- |
| 白色 | 无有效占用或限制 | 否，但仍须满足个人资格和时间规则 |
| 蓝色 | 有效个人座位占用 | 是 |
| 黄色 | M2 已生效的整室预约 | 是 |
| 红色 | M3 整室停用限制或长期禁用 | 是 |

不影响正常使用的普通维修以独立提示标记展示，不占用主色，也不影响预约。

长期禁用与维修停用通过文字原因区分。教室长期禁用作用于全部座位，单座位长期禁用仅作用于对应座位。

整室占用或停用限制同步展示在所属教室全部座位的对应时段。点击占用时段可查看“已被预约”“整教室活动”“维修停用”等原因，不展示其他学生信息。

出现多种重叠原因时，主色按“维修红色 ＞ 整室黄色 ＞ 个人蓝色”绘制，同时保留全部公开原因。颜色只是展示规则，不得代替后端冲突判断。页面同时提供文字说明，不仅依靠颜色表达状态。

展示刻度不改变实际占用精度。例如 11:10 提前结束，应展示实际释放边界，不能把 11:00～11:10 误报为空闲。

### M1-F04 选择时间段

学生选择开始和结束时间后，系统展示预约时长、当日剩余额度、取消截止时间与校验提示。前端校验仅用于交互，后端在提交时重新校验。

提交期间防止重复点击。若提交时资源已被占用，应提示冲突并刷新时间轴，不自动更换座位或时段。查询失败时显示错误与重试入口，不显示为全部空闲。

### M1-F05 我的预约

学生可分页查询本人当前及历史预约，并按日期、状态筛选。

记录展示教室、座位、原计划时段、当前状态、实际签到时间、实际结束时间及取消原因。页面按当前状态展示可执行操作，后端仍独立校验操作权限和条件。

### M1-F06 违约查询

学生可查看当月违约次数、是否达到禁约限制及对应本人预约。系统维修取消明确标记“不计违约”。

## 四、预约业务规则

### M1-R04 开放时间

自习教室每日 07:00～22:00 开放。预约开始时间不早于 07:00，结束时间不晚于 22:00，不支持跨自然日预约。

### M1-R05 预约开放窗口

使用日前一天 22:00 起开放预约，使用当天仍可预约尚未开始的时段。不得提前超过一天预约。

开始时间必须严格晚于服务端当前时间，恰好等于当前时间时也不允许创建。

所有时间判断使用校园本地时区 `Asia/Shanghai`，以服务端时间为准。例如 10 月 23 日的预约，在 10 月 22 日 22:00:00 开放。

### M1-R06 单次预约时长

单次预约最短 1 小时、最长 4 小时，两个边界均包含。

### M1-R07 时间粒度

预约起止均为整点或半点，秒及更小单位为零。例如允许 09:00～10:30，不允许 09:15～10:15。

### M1-R08 每日预约额度与重叠

不限制单个用户预约总条数，但每个使用自然日累计额度最多 4 小时。同一用户不得持有时间重叠的多个有效个人座位占用，即使属于不同座位或教室。

每日额度按预约的使用日期归属，计算规则如下：

- `RESERVED`、`CHECKED_IN` 和 `COMPLETED` 按完整计划时长计入。
- `EARLY_FINISHED` 按计划开始至实际结束的时长计入，不以签到时间缩短计入时长。
- `CANCELLED` 不计入。
- `NO_SHOW` 仍按完整计划时长计入，防止未签到后反复占座。
- `SYSTEM_CANCELLED` 未签到的不计入；已签到的按计划开始与实际签到两者较晚时刻至停用生效时刻的实际使用区间计入，并限制在原计划区间内，不足零按零计算。

新预约计入后不得超过当日 4 小时。本人记录显示当日已计入额度及剩余额度。

有效个人预约包括 `RESERVED` 和 `CHECKED_IN`。并发创建不得突破每日额度和用户重叠限制。M1 对同一用户的创建流程进行并发控制，覆盖资格、额度校验至占用及业务记录结果确认；结果未确定的创建请求暂按拟预约时长预留额度，确认失败后释放，防止重复提交绕过额度。

### M1-R09 预约冲突

以下任一情况禁止创建新预约：

1. 目标座位存在重叠的有效个人占用。
2. 当前用户存在重叠的有效个人座位占用。
3. 所属教室存在重叠的有效 M2 整室占用。
4. 所属教室存在重叠的 M3 整室停用限制。
5. 座位或教室处于长期禁用状态。
6. 用户达到当月违约禁约限制。
7. 用户无该资源的访问或预约权限。
8. 新预约将导致使用日累计额度超过 4 小时。

不影响使用的普通维修不构成冲突。

时间区间采用左闭右开形式 `[开始, 结束)`。例如 `[09:00,10:00)` 与 `[10:00,11:00)` 不冲突。两区间重叠的条件为“开始1 < 结束2 且开始2 < 结束1”。

### M1-R10 自动创建预约

M1 校验个人规则后，通过 D 原子建立占用，并保存对应业务记录。全部确认后向学生返回成功，预约状态为 `RESERVED`。

D 在同一次占用建立操作中校验座位冲突、整室限制和用户跨座位时间重叠。并发情况下，同一座位重叠时段至多一个成功，同一用户重叠时段也至多一个成功。

每次创建具有唯一请求标识，重复提交不得产生多条预约。业务记录与占用必须能相互追溯；发生部分失败时，通过查询确认结果，业务保存失败则尝试释放本次占用，不遗留无法追溯的占用。结果未确认前不宣称预约成功。

## 五、取消、签到与提前结束

### M1-R11 预约开始前取消

本人可在计划开始时刻之前，取消状态为 `RESERVED` 的预约，不设置提前 30 分钟的限制。

例如 09:00 开始的预约，08:59:59 可以取消，09:00:00 起不允许按本规则取消。成功后进入 `CANCELLED`，释放占用及对应每日额度，不记违约。

已签到预约不适用本规则。

### M1-R12 签到时间窗口

仅本人可在计划开始前 15 分钟至开始后 30 分钟签到，两个边界均包含。例如 09:00 开始，允许签到窗口为 08:45:00～09:30:00。

学生在“我的预约”中选择本人预约并点击“签到”。后端校验登录身份、预约归属、预约状态、签到时间窗口，以及是否存在已生效的停用或禁用限制；全部通过后完成签到。页面仅在满足操作条件时提供签到入口，后端仍独立校验。

成功后进入 `CHECKED_IN` 并记录实际签到时间。重复提交已成功的同一次签到返回既有结果，不重复记录。

提前签到不改变原计划占用起点，不代表可以提前使用座位。签到记录表示本人已在平台确认使用，不作为实际到场证明。

### M1-R13 签到后提前结束

仅本人 `CHECKED_IN` 预约可提前结束，且须满足“计划开始时间 ≤ 当前时间 < 计划结束时间”。

提前结束视为正常完成，不计违约。例如预约为 09:00～13:00，在 11:00 提前结束：

- 历史保留原计划时段 09:00～13:00。
- 记录实际结束时间 11:00。
- 通过 D 释放 11:00～13:00 的占用。
- 状态更新为 `EARLY_FINISHED`。
- 按实际结束时间重算当日额度。

实际结束时间不要求为整点或半点。11:10 结束后，后续新预约仍须按半小时边界提交，因此最早可选择 11:30 开始。

08:50 提前签到者须等到 09:00 才能提前结束。到达计划结束时间后按自然完成处理，不再接受提前结束。

### M1-R14 未签到违约

严格超过计划开始后 30 分钟且仍未签到时，系统自动：

1. 将预约状态改为 `NO_SHOW`。
2. 释放剩余座位占用。
3. 记录一次未签到违约。
4. 保留本人历史记录。

09:00 开始的预约，09:30:00 仍允许签到，超过该时刻才符合违约条件。超出窗口不能因定时任务尚未执行而签到成功。

签到与超时任务须使用一致时间口径及并发控制，不能同时产生签到成功和违约结果。同一预约重复执行超时处理只计一次违约。

### M1-R15 月度违约限制

同一自然月累计 3 次 `NO_SHOW` 后，当月不得创建新的个人预约，已有有效预约继续保留。

违约月份取原计划开始日期所属月份，不取任务执行月份。创建预约时按请求发生月份判断是否禁约，因此本月禁约者也不能在本月提前预约次月时段。

进入新月后按新月份累计，不删除历史。M3 停用导致的系统取消不记违约。

创建前须核实本人已超过签到截止时刻但尚未处理的待签到预约，完成应有的违约判定后再检查禁约资格，不能仅依赖定时任务已更新的计数。新预约资格确认与第三次违约判定采用同一用户范围内的一致并发控制：若第三次违约已满足业务条件，不得因处理延迟接受新预约；此前已确认的预约仍保留。

### M1-R16 自动完成

已签到、未提前结束且未系统取消的预约，到达计划结束时间后自动进入 `COMPLETED`，学生无需主动签退。

即使状态更新任务暂未执行，原占用也不得阻止计划结束之后的合法预约。

## 六、M2、M3 跨模块联动

### M1-R17 M2 整室占用

M2 仅在两级审批完成且 D 成功建立整室占用后正式生效。

对应时段内，所有所属座位禁止新个人预约，时间轴显示黄色。普通整室申请不得覆盖已确认的个人预约。

M2 与 M1 并发提交冲突占用时，由 D 原子判定，不能双方成功。M2 撤销只释放对应申请来源的占用，不清除其他预约或维修限制。

### M1-R18 M3 普通维修

M3 确认维修不影响正常使用时：

- 不创建阻止预约的限制。
- 不取消已有 M1/M2 预约。
- 不阻止新增 M1/M2 预约。
- 仅在时间轴展示维修提示。

### M1-R19 M3 整室停用

必须立即停用的安全故障，从 M3 确认或实际发现必须停用的时刻生效，不等待维修人员到场。

此前仍可安全使用的计划施工，按确认的未来施工时段向 D 申请限制。若与已确认 M1/M2 预约冲突，默认拒绝建立，由 M3 调整施工安排；不得直接以普通计划施工取消既有预约。

维修紧急程度、停用范围及生效时间由 M3 授权人员确认并留痕，M1 不判断安全性。

### M1-R20 紧急维修冲突处理

紧急安全停用优先于已有预约。D 先建立限制、阻止新占用，再通知 M1 处理受影响预约，不等待业务取消全部完成才阻断预约。

对于与停用区间重叠的 `RESERVED` 或 `CHECKED_IN` 预约，M1：

1. 将状态更新为 `SYSTEM_CANCELLED`。
2. 保留原计划时段、签到信息，记录原因、来源工单、停用生效时间和处理时间。
3. 已开始使用的预约记录被迫结束时间，未开始预约记录系统取消时间。
4. 通过 D 释放该预约自终止时刻起的剩余占用。
5. 不计违约，并按 M1-R08 重算当日额度。

紧急停用的终止时刻为停用生效时刻；停用晚于原计划开始时，保留此前已发生的使用记录。尚未开始的预约释放全部未来占用。学生通过“我的预约”查看处理结果。

解除停用后，已取消预约不自动恢复，学生须重新预约。

### M1-R21 停用恢复与多来源限制

M3 确认恢复条件后，仅请求解除对应工单的限制。其他工单、M2 占用、个人预约和长期禁用状态继续有效。

D 根据全部有效来源计算可用性，不直接将教室全部座位设置为空闲。新增、变更和解除均可追溯到来源业务记录。

### M1-R22 延迟、重复与乱序通知

重复停用或恢复通知不得重复取消、释放、记违约。限制的新增与解除按来源记录校验，不能解除其他来源的限制。

以可信业务生效时间裁决停用与违约的先后关系。停用在签到截止时刻或之前生效且与预约重叠时，学生不记未签到违约；若因消息延迟已经误记，则更正预约结果，撤销对应违约事实并重算该月资格及对应使用日额度，保留原记录及更正原因。

停用晚于已经有效发生的违约时，不追溯免责。停用在计划结束后才生效，不回改已正常完成的预约。

## 七、预约状态与流转

| 状态 | 含义 |
| --- | --- |
| RESERVED | 已确认，待签到 |
| CHECKED_IN | 已签到，尚未结束 |
| CANCELLED | 本人按规则取消 |
| NO_SHOW | 超时未签到 |
| EARLY_FINISHED | 本人提前结束，正常完成 |
| COMPLETED | 已签到并自然完成 |
| SYSTEM_CANCELLED | 因紧急停用被系统取消 |

| 原状态 | 触发条件 | 目标状态 |
| --- | --- | --- |
| 无 | 规则通过且占用确认成功 | RESERVED |
| RESERVED | 计划开始时刻之前本人取消 | CANCELLED |
| RESERVED | 窗口内本人点击签到并通过后端校验 | CHECKED_IN |
| RESERVED | 严格超过签到截止时刻 | NO_SHOW |
| CHECKED_IN | 到达开始但未到结束，本人提前结束 | EARLY_FINISHED |
| CHECKED_IN | 到达计划结束 | COMPLETED |
| RESERVED / CHECKED_IN | 紧急停用影响预约 | SYSTEM_CANCELLED |

终态不接受普通用户重新激活。只有 M1-R22 定义的可信延迟事件更正可修正误判，并保留更正原因。

## 八、异常处理与一致性

### M1-R23 操作与错误处理

创建、取消、签到和结束操作均由后端校验身份、业务状态和规则。重复点击不能产生重复预约、重复签到或重复违约。同一预约的签到与超时、取消与签到等竞争操作只能形成一个合法结果。

创建时先校验个人规则，再调用 D 建立占用；失败时返回明确错误，不显示成功。若占用已成功而业务记录保存失败，应尝试释放本次占用；结果无法确认时提示刷新查询，不自动重新创建。跨模块失败的基础处理通过接口返回值与已有记录查询完成，首版不建设独立补偿平台。

对未登录、无权限、非法时间、额度不足、违约禁约、资源冲突和接口失败提供清晰提示，不泄露他人信息。

### M1-R24 自动处理

未签到判定和自然完成通过普通后台定时任务处理，正常运行时每 60 秒检查一次。重复执行不重复产生违约。签到窗口和占用截止均以业务时间为准，不能因任务尚未运行而延长。

教室停用影响的预约，由模块接口完成状态更新；不要求引入消息队列、事件投递平台或运维控制台。

## 九、首迭代范围与验收

### 9.1 首迭代范围

包含教室与座位浏览、插座筛选、时间轴、预约、本人记录、每日额度、“我的预约”点击签到、取消、提前结束、自动完成、违约和维修联动。

暂不包含站内通知中心、提醒服务、复杂审计查询、自动对账平台、运维控制台、精确教室平面图、原座位一键再约、复杂运营报表、时长规则管理页面、定位签到、人脸识别和完整申诉审批流程。相关问题可通过团队现有反馈渠道处理，不能由普通学生自行更改违约记录。

### 9.2 核心验收场景

| 场景 | 预期结果 |
| --- | --- |
| 未登录或操作他人预约 | 拒绝，不泄露他人信息 |
| 使用日前一天 21:59:59 与 22:00:00 预约 | 前者未开放，后者可进入后续校验 |
| 预约 1 小时、4 小时、半小时边界 | 合法；不足 1 小时、超过 4 小时、跨日或非半小时边界拒绝 |
| 两人并发预约同一座位重叠时段 | 至多一个成功 |
| 同一人并发预约不同座位重叠时段 | 至多一个成功；相邻不重叠时段可成功 |
| 09:00 预约在 08:59:59 与 09:00:00 取消 | 前者成功并回退额度，后者拒绝 |
| 当日已计入 3 小时，再约 1 小时或 1.5 小时 | 前者符合额度，后者拒绝 |
| 同一用户并发创建不重叠预约 | 总额度不超过 4 小时，未知结果预留额度不被重复使用 |
| 提前结束、主动取消、未签到、系统取消 | 分别按 R08 重算额度，不混用计划时长与实际使用时长 |
| 第三次违约已到期但任务尚未处理，立即提交新预约 | 核实违约后拒绝创建，不因计数延迟放行 |
| 同一预约变更结果未知时提交冲突操作 | 先确认原结果，不产生相互矛盾状态 |
| 长期禁用教室或座位 | 对应范围红色并注明长期禁用，拒绝预约 |
| 本人在“我的预约”中点击签到 | 后端校验身份、归属、状态、窗口和有效限制，通过后记录签到时间；重复请求不重复记录 |
| 09:00 预约在 08:45:00、09:30:00 签到 | 本人预约状态与资源条件合法时均可成功；窗口外拒绝 |
| 签到与超时任务并发 | 只有一个合法结果，不同时签到成功并记违约 |
| 提前签到后在开始前尝试提前结束 | 拒绝；到达开始时刻后允许 |
| 09:00～13:00 在 11:10 提前结束 | 保留原计划，记录 11:10，释放剩余占用；后续可从 11:30 预约 |
| 同月第三次未签到及重复执行任务 | 达到禁约且只记一次；已有预约保留 |
| 上月违约在次月延迟处理 | 归属上月，不误计本月 |
| 已签到预约到达结束时间 | 自然完成，不阻止之后时段预约 |
| M2 生效与 M1 并发建立冲突占用 | 不能双方成功；有效整室时段全部座位黄色 |
| 普通维修 | 仅提示，不取消或阻止预约 |
| 计划施工与已有预约冲突 | 拒绝该施工限制，不自动取消预约 |
| 紧急停用 | 立即阻止新预约，取消受影响预约，保留原因、不计违约 |
| 解除一张工单，仍有其他限制 | 其他限制继续有效，不无条件恢复空闲 |
| 停用消息延迟或重复 | 正确更正误记违约，无重复副作用 |
| 查询失败或创建响应丢失 | 不误报空闲或成功，可查询并幂等恢复 |

本文为需求评审稿，验收场景尚未执行，不表示相关功能已经实现。正式开发时为需求关联实现与验证记录。
