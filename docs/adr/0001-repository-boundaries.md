# ADR-0001：仓库组织与模块边界

- 日期：2026-10-14
- 状态：待团队评审；初始化采用目录提案，不表示团队已达成架构共识
- 提议：本次 AI 辅助初始化
- 决策人、评审人、一致过程：待补
- 依据：任务书正文及附件 1、本次初始化任务

## 背景

六人至少三个模块组，共享环境，维护公开契约、数据演进及交付证据。M2/M3 写回 M1，M1 来源追溯，期末需要网络调用。D 归属和插件技术未定。

## 候选与权衡

| 方案 | 收益 | 成本/风险 |
| --- | --- | --- |
| 多仓库独立服务 | 发布自治、物理边界明确 | 六人协调成本高，不符合本次 Monorepo 要求 |
| Monorepo 混合所有业务 | 初始装配简单 | 易跨表耦合，职责及网络集成难维护 |
| Monorepo 显式模块及集中契约 | 便于分工、评审、全组交付且保留部署选择 | 必须执行边界、网络适配和一致性规则 |

## 初始化采用的提案

采用第三种：前后端分离，后端 M1/M2/M3/D，契约、跨模块测试、迁移/种子、运维/CI、需求/ADR/伦理与插件独立组织；使用真实约定文档，不建分层空文件。

跨模块公开网络 API，不依赖内部代码/表；服务进程数未决定，不能据此声称已选微服务。D 管理主数据、M1 管理预约和有效限制，具体所有权待细化。

## 影响与待决

协作和插件有稳定入口，但目录不会自动保证边界，需要评审与测试。待决：D 归属、服务/网关拓扑、数据库隔离、冲突/重试/补偿、工具、云资源及发布顺序。

D 归属特别比较单组承担与子域分担，记录均衡、公平性、契约治理、故障责任及一致过程；本提案不代分配负责人。
