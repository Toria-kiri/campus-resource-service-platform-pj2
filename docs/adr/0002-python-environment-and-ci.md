## 背景与候选

六人需要本地与 CI 共用依赖和基础检查。仓库仅有目录与文档，M1/M2/M3 没有独立发布包或不同依赖需求。

| 方案 | 收益 | 成本与影响 |
| --- | --- | --- |
| 每模块单独配置和锁文件 | 依赖独立 | 重复维护，版本容易漂移 |
| uv workspace 多包、共享锁文件 | 共享解析，支持包级元数据 | 当前尚无独立包需求，增加配置和打包成本 |
| 根目录单项目、单锁文件 | 初始化简单，六人使用相同命令 | 依赖需协同升级；未来独立交付需求需重新评估 |

## 本次采用

采用根目录非发布项目：Python 3.12（requires-python 限制为 >=3.12,<3.13）、uv 0.13.1、统一 `.venv` 与 `uv.lock`；运行依赖为 FastAPI/Uvicorn，dev 组为 pytest/httpx/Ruff。不新增数据库、全局业务框架或服务。

`.python-version` 指定 3.12 系列，两平台使用相同文件；补丁版本可能随 Python 安装源更新，不宣称永久固定补丁版本。uv 通过 required-version 精确约束，包精确版本与平台条件由锁文件记录。

M1/M2/M3 各提供最小应用入口，不聚合业务、不互相导入。三个本地端口只用于开发验证，不决定生产进程数、网关或部署拓扑；沿用 [ADR-0001](0001-repository-boundaries.md) 的领域边界。

CI 在所有 PR 与 main Push 时使用 Windows/Ubuntu 矩阵。安装 uv/Python 后依次执行 locked sync、Ruff lint、格式检查和 pytest，失败即失败；Actions 引用固定提交，权限仅 contents:read。命令不含平台特有路径或 shell 语法，pytest 使用 importlib 收集同名测试。

## 影响、风险与待决

首次同步需要联网；`--locked` 防止隐式改锁，依赖升级需显式评审。单锁文件不授权跨模块访问内部逻辑。环境路径和绝对路径不入库。

测试真实执行 ASGI 应用，本地另外进行 Uvicorn 网络启动验证；不声称已验证业务集成。Ubuntu CI 结果须等待 GitHub Actions 实际执行。分支保护、必需状态检查及组内人工评审仍须负责人配置或核实。

完整构建交付、测试自动部署、生产审批、数据库迁移和插件交付未纳入此次范围，保留在需求追踪中。
