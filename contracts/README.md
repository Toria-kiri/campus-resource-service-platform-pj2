# 公开 API 与跨模块契约

维护公开接口约定，后续加入 OpenAPI 等可验证描述；当前仅定义 M1/M2/M3 的最小 [health 接口](health.md)，无业务端点。提供方和调用方共同评审，跨模块/D/schema 影响经组内评审。

每份契约包含需求 ID、提供方/调用方、权限、版本、请求/响应/错误、时区与区间边界、来源业务 ID、幂等/关联标识、冲突、重复/乱序处理、超时重试、补偿和兼容性。路径/字段/协议待团队确认。

| 链路 | 必须表达的行为 |
| --- | --- |
| M3 → M1 | 维修中全室下架，验收通过撤销对应工单限制，多工单不相互覆盖 |
| M2 → M1 | 通过全室时段占用，驳回/超时撤销对应申请占用，保留其他来源 |
| M1 追溯 | 个人预约、审批占用、维修下架均记录来源和业务关联，解释当前状态依据 |
| 模块/插件 → D | 公开接口使用主数据/授权、通知和审计，禁止跨表读写 |

恢复不能无条件覆盖为可预约。既有个人预约遇审批/维修、同步 HTTP 是否配合异步机制、时序/重试/补偿及追溯查询待决。新增能力优先扩展公开接口；破坏性变更同步版本、调用方和迁移顺序。

至少一条链路须真实网络调用演示；契约及集成测试放 `../tests/`，插件遵守相同接口。
